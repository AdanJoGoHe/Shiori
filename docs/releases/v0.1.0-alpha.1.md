# Shiori v0.1.0-alpha.1

Package version: `0.1.0a1` (PEP 440). Personal Codex alpha; not the full v1 specification.

The [manual Release workflow](../release-workflow.md) validates Windows/Linux and prepares a
draft by default. Owner dispatch/publication remains a separate step; merging workflow code
does not create the release.

## Included

- Canonical Markdown capture, revisions, journal-only progress, exact metadata filters and bounded agent context.
- Explicit quality preview and pending-event inspection/retry ordering.
- Loopback library, Claro/Oscuro/Café Latte, separate highlights/categories and conservative anchor repair.
- Global marked-fragment search by category/color, exact quote copy, short context and reader navigation.
- Local recovery bundle and restore into a fresh paused deployment.
- Portable skill packaged inside the wheel, reversible Codex registration, owned integration
  upgrade with preview/recovery snapshots.

## Installation and upgrade

When a release is published, download its wheel and matching constraints, verify SHA256SUMS, and
use Python3.12. The constraints preserve the tested dependency set; no PyPI publication is implied.

```powershell
uv venv --python 3.12 .venv
uv pip install --python .venv --constraint second_brain-0.1.0a1-constraints.txt second_brain-0.1.0a1-py3-none-any.whl
```

An existing personal deployment keeps its config/vault/state. Preserve an independent local backup
before switching runtimes; `backup --output` requires a new private directory. Do not copy private
state into a source checkout. `restore` creates new paths and stays paused; it does not switch hosts.
See [recovery instructions](../backup-restore.md) for limits and excluded machine settings/ACLs.

For a fresh deployment, create a config JSON in an approved private directory with schema_version1,
scopepersonal, timezoneEurope/Madrid and absolute vault_path/state_path/basic_memory_config_dir.
The example [personal configuration](../../config/personal.example.json) shows the schema; choose
new private paths rather than copying this owner's paths. Run the installed interpreter with
`-m second_brain.cli --config <config.json> doctor`, then `install-codex` for explicit host setup.
The installer refuses an unmanaged existing server/skill; it does not overwrite custom integrations.
For an upgrade, use the destination interpreter and existing configuration with `upgrade-codex`
to preview, then `upgrade-codex --apply` after stopping host processes. Modified owned files are
refused; recovery snapshots and unrelated settings are retained. See the
[update procedure](../actualizacion.md). `uninstall` preserves notes and unrelated settings.

Reconnect/restart Codex to discover all eight tools after updating runtime/skill. The global
instructions only point to the skill. `get_context` and filtered canonical search do not start
Basic Memory. A newly restored provider directory has no configured project/index; provider setup
is separate, and unavailable provider search falls back to the filesystem. No hooks are installed.

## Validation and limits

Release preparation passed185 tests (one Windows native-symlink privilege skip), Ruff lint/format,
and an isolated wheel installation from outside the checkout. `scripts/verify-release.py` exercises
skill packaging, install/uninstall preserving unrelated settings, CLI capture/context/dedupe, all
8 fresh-stdio tools, scope/secret rejection, viewer resources/cross-origin denial and backup/restore
without the original config. CI repeats source tests and clean-wheel acceptance on Windows/Linux.
Actual Codex has exercised canonical search/read/capture/read-after-write; this running chat caches
6 tools. Classifier/pending discovery after reconnect is not claimed for this already running chat.
Fresh stdio verifies all8, not another product host or capture-rate study.

Subsequent integration-upgrade validation passed203 tests (one Windows privilege skip), plus
installed-wheel upgrade preview/apply/retry and the existing smoke. This uses a synthetic prior
owned skill, not an upgrade between two published releases; package migration remains manual.

Provider reliability follow-up passed229 tests (one Windows privilege skip) and a real Basic
Memory indexed search from the installed wheel on a synthetic local project. MCP status now
reports a process-local observation; [provider diagnostics](../provider-search.md) document
safe fallback codes and configuration checks. It is not a live health probe or latency claim.

An explicit availability check is now available through `doctor --provider` and MCP
`memory_status(check_provider=true)`: bounded local project status, no reindex, no observed paths
in the response. Default status remains passive. Installed-wheel acceptance exercises both
entries; availability alone does not prove index freshness or successful search.

Known alpha limits: agent-declared quality/evidence; regex cannot certify prose; retries require
original JSON; multi-file capture is recoverable rather than transactional; backups are plaintext,
unsigned and inherit destination ACLs. No secure-erasure promise or downgrade across annotation
schemas. No automatic learning/hooks, corporate deployment, Claude/Augment acceptance,
graph/timeline or whole-vault latency claim. Starting the viewer does not install an OS service.

## Review and rollback

Standards review: no new hard documented-standard violations. Spec review: packaged-skill and
machine-specific fallback blockers found and fixed. Both reviews were independent/read-only;
synthetic execution supplies the acceptance evidence. Prior open PRs25,26,35,36,37,46,48–55 are
consolidated into the alpha integration PR; broader issues remain open for acceptance.

To roll back, preserve the current vault/state and select the prior runtime/config explicitly.
Do not restore over existing data. New annotation schema2 cannot be read by older schema1 builds;
retain a compatible independent backup before first mutation. Release artifacts contain source,
wheel, pinned constraints and checksums only; no vault/config/log/session artifacts.
