# Shiori v0.1.0-alpha.6

Una alpha para que los agentes usen el CLI con menos pasos y mensajes más claros.

## Qué cambia

- `shiori.cmd run --help` muestra los comandos; un comando desconocido muestra las opciones.
- `search --id` busca un ID exacto y distingue una nota ausente de una coincidencia de texto.
- Puedes buscar solo con `search --tag ...`. Las etiquetas coinciden completas y varias
  etiquetas se combinan con AND; ese filtro ya existía, ahora no exige una consulta de texto.
- `read --format text` devuelve Markdown sin los escapes de una cadena JSON.
- `classify --request-file -` y `capture --event-file -` leen JSON por stdin.
  Los archivos siguen disponibles para conservar los candidatos originales y reintentarlos.
- `note --request-file ...` muestra la propuesta y las búsquedas relacionadas.
  Solo `--apply` guarda el candidato clasificado; `--expect-revision` permite rechazar una
  revisión obsoleta. Las actualizaciones incluyen un diff acotado contra la nota actual.
- Los diagnósticos propios de conexión MCP y ambas skills indican el CLI de respaldo de la
  misma instalación. Un error del host antes de arrancar Shiori depende de ese host.

La [guía del CLI](https://github.com/AdanJoGoHe/Shiori/blob/v0.1.0-alpha.6/docs/agent-cli.md) tiene ejemplos,
límites de entrada, diffs y recuperación de capturas inciertas.

## Instalar o actualizar

Para una instalación gestionada, `shiori.cmd update --prerelease` consulta la alpha publicada;
`shiori.cmd update --prerelease --apply` la instala después de cerrar MCP y visor.
Los borradores no aparecen en el updater. También puedes usar los cinco archivos de la misma
release siguiendo la [guía de actualización](https://github.com/AdanJoGoHe/Shiori/blob/v0.1.0-alpha.6/docs/actualizacion.md).

Una memoria personal usa el Python y la configuración de su propia conexión MCP. Actualiza
su integración desde el entorno de destino. El instalador de trabajo es para un destino nuevo,
separado; no sustituye una instalación personal. Reinicia MCP y abre otra conversación para
cargar las herramientas y la skill nuevas. Una skill editada se conserva y requiere revisión.

No hay migración del esquema de notas o ledger. El formato por defecto de `read` sigue siendo
JSON. Publicar un paquete no cambia las instalaciones existentes ni activa acceso remoto.

## Comprobaciones y límites

La preparación comprueba Windows, el wheel instalado en perfiles sintéticos personal/trabajo
y la actualización desde el paquete publicado alpha.5 con rollback. Los resultados finales
se registran en la PR de preparación. No equivale a una actualización entre dos
releases públicas mientras alpha.6 siga sin publicar.

La [aceptación real en Augment JetBrains](https://github.com/AdanJoGoHe/Shiori/issues/2) sigue
pendiente. No se instala captura automática ni se promete aceptación de Linux u otros hosts.
Un fallo de transporte tras una escritura puede tener resultado incierto: conserva el evento
y candidato originales, consulta estado/pendientes y evita repetirlo con otro ID.
