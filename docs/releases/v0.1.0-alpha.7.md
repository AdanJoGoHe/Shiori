# Shiori v0.1.0-alpha.7

Un visor más cómodo para volver a tus comandos, notas y trabajo de cada día.

## Qué trae

- **Inicio y búsqueda:** accesos a textos marcados, páginas, favoritos y avances de Hoy. El
  buscador permite elegir Biblioteca, Fragmentos, Favoritos, Diario o Agent log, con filtros
  propios y contexto cerca de las coincidencias.
- **Lector:** resultados al lado o lectura centrada, búsqueda temporal dentro de la página,
  navegación entre coincidencias y copia exacta de textos marcados. Volver conserva consulta,
  filtros y posición. Los tres temas siguen disponibles.
- **Diario:** Hoy, Ayer y cualquier mes conservado, incluidos los antiguos. Los pendientes
  actuales mantienen su historial aunque consultes otra fecha o busques un avance concreto.
- **Favoritos:** páginas y referencias web guardadas por perfil, consultables desde el visor,
  MCP y CLI. Guardar un enlace no descarga ni verifica su contenido.
- **Agent log:** acciones informadas por el agente, comandos y referencias por día, sesión y
  proyecto. Se activa explícitamente en cada perfil y declara cobertura parcial.
- **Tareas:** fichas por código, como `DEMO-1234`, para reunir notas, marcas y enlaces.
- **CLI para agentes:** ayuda con comandos visibles, IDs y etiquetas exactos, lectura como
  texto, JSON por stdin, propuestas con diff y `note --apply` para revisar antes de guardar.
  El servidor anuncia 13 herramientas MCP; las dos skills incluyen los respaldos compatibles.

La alpha.6 se quedó como borrador interno anterior al visor. Esta candidata reúne sus mejoras
del CLI y el visor posterior. La publicada anterior con la que se ensaya la actualización es alpha.5.

## Actualizar cuando esté publicada

En una instalación gestionada, cierra sus sesiones MCP/visor y ejecuta:

```powershell
.\shiori.cmd update --prerelease
.\shiori.cmd update --prerelease --apply
```

Mientras sea un borrador no aparecerá en el updater. También puedes usar los cinco archivos
de la misma release con `update --release-dir` siguiendo la
[guía de actualización](https://github.com/AdanJoGoHe/Shiori/blob/v0.1.0-alpha.7/docs/actualizacion.md).
La instalación personal conserva su propio Python/configuración e integración; el instalador
de trabajo crea un perfil separado. Publicar no actualiza instalaciones existentes.

Reinicia la conexión MCP para descubrir las herramientas. En actualizaciones con archivos
locales, revisa y aplica la skill gestionada con `augment --apply`; una skill editada se conserva
y necesita revisión. La guía explica también la integración personal.

## Datos y recuperación

Notas, marcas, diario, pendientes, fichas de tareas, favoritos y Agent log forman el conjunto
de recuperación definido. Backup/restauración valida formato, alcance y hashes, y restaura en
un destino nuevo y pausado. Documentos externos, configuración del host, índices del proveedor
y skills aprendidas necesitan sus copias aparte; no es una imagen completa del equipo.

Al crear almacenes de favoritos, fichas o Agent log, una versión anterior puede dejar de ser
compatible. El runtime actual rechaza activarla y conserva la recuperación. No borres archivos
para forzar el rollback. Usa una restauración separada y compatible si necesitas recuperar una
memoria anterior. Quitar un favorito o corregir un log no borra copias históricas de backups.

## Validación y límites

La PR de preparación registra los resultados del wheel exacto: actualización desde el paquete
público alpha.5, recuperación conjunta, rollback compatible y rechazo del incompatible, perfiles
ficticios personal/trabajo, recorridos del visor y escenarios de volumen. No se usa la memoria real.

La validación local es en Windows; no acredita Linux ni aceptación dentro de Augment JetBrains
([pendiente #2](https://github.com/AdanJoGoHe/Shiori/issues/2)). No activa captura automática,
ejecución de comandos desde el visor ni acceso remoto. Agent log depende de lo que informe el
agente; un resultado incierto requiere conservar el evento original y comprobar su estado.
