# Shiori v0.1.0-alpha.8

Más fácil encontrar un comando y retomar una incidencia con el agente.

## Qué trae

- **Búsqueda local.** Los IDs, comandos, IP y rutas literales tienen prioridad. SQLite FTS5
  encuentra variantes como `revision` y `revisión`. El contexto muestra un extracto, la
  evidencia, los vínculos con fichas y notas, y si toca revalidar la información.
- **Fichas y checkpoints.** El MCP local puede leer y editar fichas, consultar su contexto
  con el último avance, y guardar un checkpoint junto con una decisión o nota revisada.
  Un reintento usa el mismo evento y conserva el historial.
- **Agent Log por sesión.** Puedes abrir una sesión temporal y elegir agente, proyecto y
  tipos de acción. El visor muestra cuándo caduca y permite cerrarla conservando el
  historial. Cada acción se envía después de revisarla.
- **Skill de trabajo más corta.** `shiori-work` abre la guía de búsqueda, captura, tareas,
  Agent Log, aprendizaje o recuperación cuando hace falta.
- **Oscuro · Luz de luna.** Tonos azules en el visor, con más contraste entre menús y textos.

La [comparación local](https://github.com/AdanJoGoHe/Shiori/blob/v0.1.0-alpha.8/docs/agent-efficiency.md)
recorre cinco tareas con datos ficticios. Frente a alpha.7, pasó de 14 a 9 llamadas y de
7.775 a 4.033 bytes de respuesta por ronda típica.

## Actualizar

En una instalación gestionada de Windows, cierra las sesiones MCP y el visor de ese perfil:

```powershell
.\shiori.cmd update --prerelease
.\shiori.cmd update --prerelease --apply
```

Vuelve a conectar el MCP. El servidor local anuncia 18 herramientas. Para actualizar con
archivos descargados usa el bundle completo de esta versión y refresca la skill con
`augment --apply`. La [guía de actualización](https://github.com/AdanJoGoHe/Shiori/blob/v0.1.0-alpha.8/docs/actualizacion.md)
cubre también la instalación personal y el rollback.

## Volver atrás

La alpha.7 puede leer el almacén de fichas anterior. Las ediciones de fichas por MCP y los
checkpoints usan formatos nuevos. Si hay uno pendiente, completa el reintento con el candidato
original antes de cambiar de versión. Si el runtime anterior no puede leer los datos, el updater
conserva la versión activa y guarda un respaldo. Puedes restaurar un respaldo anterior compatible
en un perfil separado y pausado.

Cierra una sesión configurada del Agent Log antes de volver a alpha.7. El cierre conserva
las acciones registradas. Al restaurar un respaldo, la autorización temporal se descarta.

La validación de esta versión usa Windows y perfiles ficticios. La prueba dentro de Augment
en JetBrains sigue en [#2](https://github.com/AdanJoGoHe/Shiori/issues/2).
